# Matriz de migración — Landing V5 a Elementor Atomic V4

**Fase:** MF-003, análisis de solo lectura
**Ámbito WordPress:** staging únicamente; la página 153 fue inspeccionada en lectura y no se modificó.

## 1. Capacidad MCP observada

El inventario MCP y los esquemas consultados confirman estos flujos:

| Necesidad | Herramienta MCP / soporte observado | Alcance y límite |
|---|---|---|
| Leer árbol Elementor | `elementor-get-page-structure` | Devuelve IDs reales, `elType`, tipo de widget, versión V3/V4 y nodos anidados. `include_content=true` con `element_id` añade settings/estilos V4 de forma legible. Sólo funciona con documentos guardados con Elementor. |
| Descubrir Atomic | `elementor-list-widget-schemas` | Resumen y esquemas consultables por tipo. Disponibles, entre otros: `e-flexbox`, `e-div-block`, `e-grid`, `e-heading`, `e-paragraph`, `e-button`, `e-image`, `e-svg`, tabs, accordion, forms y background-video. |
| Crear estructura V4 | `elementor-build-composition` | Construye una jerarquía de elementos con IDs de configuración únicos y el servidor asigna IDs reales. `append` conserva hijos; `replace_children` elimina los hijos directos del padre señalado. Escribe y guarda el documento: no se usaría durante esta auditoría. |
| Editar árbol existente | `elementor-manage-elements` | Actualiza, elimina, mueve o duplica hasta 50 elementos. Puede tener éxito parcial; IDs V4 reales y cuidado con operaciones read-modify-write. |
| Estilos/clases por elemento | `style` en `build-composition` y `manage-elements`; además `elementor-manage-classes` | CSS local admite pseudoestados y breakpoints `@media(--mobile)` / `@media(--tablet)` según las instrucciones del servidor. Las clases gestionadas por herramienta son globales del kit, por lo que no se deben crear/actualizar en esta fase ni usarlas como aislante accidental. |
| Variables / estilos predeterminados globales | `elementor-manage-global-variable`, `elementor-manage-default-styles` | Operaciones globales del kit/sitio. No apropiadas para esta migración sin autorización separada. |
| Recursos de medios | `elementor-list-assets` | Sólo lectura de los activos ya existentes en la biblioteca; devuelve IDs, URL, MIME, dimensiones y alt. `e-image` acepta IDs de medios; `e-svg` requiere un SVG cargado/permitido por el esquema. No se halló herramienta MCP de carga de archivos locales. |
| Componentes reutilizables | `elementor-list-components` | La respuesta de staging fue `components: []`; capacidades reportadas: crear/editar/insertar. MF-003 no creó componentes. |
| Interacciones nativas | `elementor://interactions/schema` | Triggers `load`, `scrollIn`, `scrollOut`, `scrollOn`, `hover`, `click`; efectos `fade`, `slide`, `scale`, `custom`, con timing y keyframes tipados. No equivale por sí solo a toda la lógica JS fuente. |
| Previsualización | `elementor-create-preview-link` | Crea snapshot temporal para un post, pensado para validación propia; su URL es temporal y no se debe presentar como permalink persistente. |

Se consultaron los esquemas de `e-flexbox`, `e-div-block`, `e-grid`, `e-heading`, `e-paragraph`, `e-button`, `e-image` y `e-svg`. En particular, `e-grid` exige configurar `grid-template-rows` para el número real de filas; no dejar filas `fr` vacías. El botón puede representarse con `e-button` y enlaces, y los contenedores V4 admiten hijos. Los estilos de responsive y el resultado público deben validarse en el editor y en viewport real: que el esquema acepte una regla CSS no garantiza igualdad visual.

## 3. Reglas de decisión para preservar fidelidad

1. Mantener texto, orden, composición, assets, rutas de CTA y comportamiento observados en los tres HTML. No reemplazar la V5 con el Hero de prueba ni con las etiquetas de otro diseño.
2. Usar Atomic para el árbol editable: secciones, grids, textos, encabezados, botones e imágenes. Un diseño editable no obliga a desechar CSS de alta especificidad cuando sea el mecanismo correcto para un efecto singular.
3. Mantener cada efecto personalizado en una hoja/archivo pequeño y versionado; no pegar todas las 39 KB de reglas en widgets, ni crear CSS global.
4. Comparar primero la composición original y la versión Atomic en las mismas anchuras, contenido e idioma. Clasificar toda diferencia deliberada en el PR antes de aceptarla.
5. Los IDs de elemento deben obtenerse del árbol o de la respuesta de creación; nunca generarse a mano ni reutilizar IDs de otra revisión del documento.
6. No usar `replace_children` en el documento raíz ni borrar el árbol de la página 153. Inspeccionar primero y preferir inserciones/ediciones dirigidas a los IDs reales autorizados.

## 4. Validación por componente

Para cada sección: estructura/orden del árbol V4; captura a 1440, 1024, 760, 390 y 360 px; texto completo ES/EN/FR; links operativos; navegación por teclado; contraste y reduced-motion. Añadir pruebas específicas de modales (focus trap y restore), escena (scroll y resize), menú (ARIA, Escape y fallback) y activos (carga, dimensiones, recorte y alt).

La matriz es un plan de migración, no una afirmación de que se verificó un render final ni de que los efectos se hayan implementado en WordPress.
